# Full-page capture quality

Rebuilt 2026-10-06 using ScreenshotOne's [full-page Playwright article](https://screenshotone.com/blog/a-complete-guide-on-how-to-take-full-page-screenshots-with-puppeteer-playwright-or-selenium/), [section-capture guidance](https://screenshotone.com/docs/guides/full-page-screenshots/), and [page-readiness article](https://screenshotone.com/blog/playwright-wait-for-page-to-load/). Desktop presets and custom viewport defaults use deviceScaleFactor 2. A 1280×720 CSS viewport produces a 2560×1440 image. An explicit scale of 1 remains supported; mobile presets keep their native scale. Mobile pages without viewport metadata retain the browser's visible zoom.

The default `by_sections` algorithm loads and captures visible viewports during one downward scroll pass. It does not stretch the browser viewport or return to the top for a second capture pass. Visible media includes native lazy images, picture sources, common data-src/data-srcset placeholders, and lazy frames. Image load and decode waits are bounded. Each section waits for layout stability; the final viewport waits for bounded delayed growth before capture. Smooth scrolling, snapping, anchoring, and temporary visibility changes are restored.

`reduce_motion` defaults to true: request reduced motion, finish finite visible CSS/Web Animations, and pause infinite animations and playing media at their current frame during each screenshot. Recognized GSAP timelines pause temporarily. Small fixed/sticky headers appear once, including initially discovered shadow-DOM elements. Fixed bottom overlays are suppressed until the final viewport. PNG slices are stitched without lossy intermediate encoding. JPEG/WebP use the requested final quality. An explicit `native` algorithm retains lazy-load preparation followed by a browser full-page capture.

`full_page_scroll_delay` accepts 0–5000 ms; the renderer default is 400 ms. `full_page_scroll_by` accepts 120–2160 CSS pixels, capped at the visible viewport height. Its default is 85% of that height. The playground defaults to Document ready plus content/font/network checks, a 60-second budget, and incomplete-shell rejection. Explicit local quality overrides and the API's existing defaults remain supported.

Section PDFs embed RGB PNG compressed data directly using PDF image predictors, avoiding a second JavaScript decode/recompression. This follows the lossless stream technique used by [PDFKit's PNG implementation](https://github.com/foliojs/pdfkit/blob/master/lib/image/png.js). The default PDF is one continuous image-based page, preserving screen layout. Viewport PDFs and explicit native PDFs retain selectable text. PDF dimensions are CSS pixels; raster dimensions are output pixels. Tall PDFs use UserUnit when needed.

Navigation, section capture, and encoding share the remaining rendering budget. Browser startup, queueing, inspection, cleanup, and delivery can add time outside that budget. Timeout, exhausted scroll steps, and blocked scrolling fail rather than deliver partial success. Infinite content is capped at 24,000 CSS pixels by default, and diagnostics disclose truncation. Raster images also respect the pixel ceiling. Arbitrary canvas, JavaScript, embedded frames, virtualized lists, or content that changes earlier sections remain best effort and can require custom settings.

Results include `render_diagnostics`: renderer version, algorithm, section count, device scale, captured scroll height, stop reason, and truncation. The playground displays the useful evidence next to the preview; stored artifacts preserve it across cache eviction. Version 3 cache keys prevent older captures from satisfying new requests. Existing stored artifacts remain available.

The local resolver returns Stripe addresses using the well-known NAT64 prefix `64:ff9b::/96`. The public-network classifier now checks the embedded IPv4 address for that exact prefix, per [RFC 6052](https://www.rfc-editor.org/rfc/rfc6052). Translations of loopback, private, metadata, shared, and reserved ranges remain rejected. This avoids a false rejection before rendering without disabling the network guard.

Verification covers reversible reveals, a single scroll pass, delayed footer growth, lazy placeholders, finite and infinite motion, fixed/shadow headers, fixed footers, fractional scales, mobile zoom, cleanup, height limits, and tall PDFs. Live captures and timings are saved under `.qa/core-rebuild/`. PDFs are rendered independently for visual inspection.

Dynamic pages require additional screenshots, and 2× resolution produces four times as many pixels. These local checks do not establish production deployment or a universal guarantee for every website.
